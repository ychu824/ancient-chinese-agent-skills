## 来源定位

| 典籍 | 定位 | 用法 |
|---|---|---|
| 韩非子 | 御人原典，应作主干 | 二柄、主道、内储说上七术：委托-代理问题的系统论述 |
| 孙子兵法 | 讲的是将兵，不是驭人术 | 主要贡献是结构设计：势、分数、形名 |
| 史记 / 战国策 | 案例库 | 价值在失败模式，不在原则 |
| 左传 | 案例库，侧重指挥链、异议和记录 | 邲、殽两战讲指挥链失效；晏子和同、乡校讲怎么用反对意见；董狐、齐太史讲记录的独立性 |
| 春秋（经） | 极简编年，本身几乎没有可迁移的内容 | 只贡献一条：笔法，即用固定词表承载判定；其余都靠《左传》的叙事 |
| 三十六计 | 对敌诡道 | 拿来管自己人是错配，适合当 agent 的 threat model |
| 孙子兵法·作战篇 | 讲战争的成本，是全书里最接近“算账”的一篇 | 拙速、远输、因粮于敌：对应延迟、agent 之间传 context 的开销、复用现成材料 |
| 墨子·节用 | 原六部之外。专讲够用即止 | 停止规则的出处：不增加效用的花费不花 |
| 荀子·王霸 / 吕氏春秋·察传 / 论语 | 原六部之外，各取一条 | 执要（中枢只握要点）、数传失真（交接越多越走样）、欲速则不达（省流程不省底线） |

另有两条不在上表的出处：《孙子·用间》（先知者必取于人；五间俱起）用于调研的取证和多入口探查；《谷梁传·桓公五年》（信以传信，疑以传疑）用于证据等级标注。

## 框架

共 12 层 46 条。层的顺序：任势、分数、形名、同欲、参验、藏欲、兵符、试任、直书、量力、节用、执要。

前九层讲怎么把事情做对：分工、立约、验功、授权。后三层（量力、节用、执要）讲怎么少花力气：按分量选档位、够用即止、中枢只握要点。

| # | 层 | 出处 | 原文 / 典故 | 机制 | 迁移到 agent fleet | 落地：Research / 调研 | 落地：Code review |
|---|---|---|---|---|---|---|---|
| 1 | 任势 | 孙子·势篇 | 求之于势，不责于人，故能择人而任势 | 结果取决于结构，不取决于个体素质 | 先设计 harness（工具、权限、上下文流向、checkpoint），让正确行为成为阻力最小的路径；不要靠 prompt 里恳求 | 固定流水线：scope → 并行检索 → 独立核查 → 综合；每步产物落盘成文件 | reviewer 只给只读工具和跑测试的权限；默认拿 diff + 需求，不拿作者的对话 |
| 2 | 任势 | 左传·成公二年（鞌之战） | 师之耳目，在吾旗鼓，进退从之 | 全军只认一个信号源，信号源不能倒 | orchestrator 的状态外置到文件（计划、进度、已决事项），context 满了或重启后能接着跑 | 调研计划和各子问题的状态写进一个进度文件 | review 清单和每条 finding 的处理状态落盘 |
| 3 | 分数 | 孙子·势篇；史记·淮阴侯列传 | 治众如治寡，分数是也；陛下不能将兵，而善将将 | 层级编制让控制幅度恒定 | orchestrator 只管 lead，lead 管 worker；每层 fan-out 有上限 | lead 拆 3–5 个子问题，每个 sub-agent 负责一个，只回结论 + 来源，不回原始网页 | 按维度拆 reviewer（正确性 / 并发与安全 / 测试覆盖），lead 合并去重 |
| 4 | 分数 | 史记·高祖本纪 | 张良、萧何、韩信「三者皆人杰，吾能用之」 | 按能力分工，统帅不必最强 | planner、infra、executor 分离；orchestrator 用便宜模型也行，关键是路由对 | 检索用便宜快模型，综合与判断用强模型 | 机械检查（lint、格式、类型）交给工具，agent 只看语义问题 |
| 5 | 分数 | 左传·庄公十年（曹刿论战） | 一鼓作气，再而衰，三而竭 | 效力随重复衰减 | 关键工作放在 context 前段；同一个 agent 第三次重试，不如开新 context | 一个 sub-agent 只答一个子问题，不连续追加任务 | 大 PR 拆给多个新开的 reviewer，而不是一个 reviewer 看到底 |
| 6 | 形名 | 韩非子·二柄 | 以其言授之事，专以其事责其功（典衣典冠同罪） | 先陈言，后授事，按言验功；越职与失职同罚 | agent 先交 plan 和验收标准，再执行，输出对照自己的承诺检查；改了任务外的文件算失败，哪怕改得“更好”（画蛇添足） | sub-agent 先回报检索计划和“什么算答完”，交付时逐条对照；超范围的发现单列，不混入结论 | reviewer 只报问题不改代码；修复 agent 只改被指出的范围，diff 超出即退回 |
| 7 | 形名 | 史记·孙子吴起列传 | 约束不明，申令不熟，将之罪也 | 归责顺序：先查指令，再查执行者 | agent 出错先审 spec 和 context；spec 明确后仍错，才换模型或加约束 | 结果差先看 brief：是否写了目标、范围、时间窗、输出格式、已知信息 | 误报多先看是否给了需求和代码约定；没给，reviewer 只能猜 |
| 8 | 形名 | 左传·僖公三十二、三十三年（殽之战） | 孤违蹇叔，以辱二三子，孤之罪也（不替孟明） | 决策错的责任在决策者；不因上层决策失败换掉执行者 | 失败先复盘 orchestrator 的分解和 brief；critic 的反对意见必须有书面处置（采纳 / 驳回 + 理由） | 反证 agent 的结论必须进最终报告，不许静默丢弃 | reviewer 的每条 finding 都要有处置记录 |
| 9 | 形名 | 左传·昭公六年（子产铸刑书，叔向反对） | 民知有辟，则不忌于上；锥刀之末，将尽争之 | 成文规则会被按字面钻空子 | 规则清单会引出 specification gaming；写规则时附上理由和意图，验收看结果，不看是否逐条打勾 | 不要只写“至少 5 个来源”，否则会凑数 | 不要只写“每个文件至少一条意见” |
| 10 | 同欲 | 孙子·谋攻；战国策·魏策四（南辕北辙） | 上下同欲者胜；此数者愈善，而离楚愈远 | 目标错位时，能力越强偏得越快 | 每个 sub-agent 都要拿到顶层目标和“为什么”，不只拿子任务；先验方向再加并发 | brief 里写明这次调研服务于哪个决策，否则 sub-agent 会交回“全面但无用”的综述 | 告诉 reviewer 这个改动要达成什么，否则它只会挑风格 |
| 11 | 参验 | 韩非子·内储说上七术 | 众端参观、一听责下、挟知而问、倒言反事 | 多源交叉、逐个问责、明知故问、反向试探 | 独立 verifier；按单个 agent 评估而非只看合奏（滥竽充数）；埋 golden case 和 canary；注入故障看能否被发现 | 每条关键结论要求可点开的来源；抽查若干条回原文核对；埋一个你已知答案的问题 | 定期喂一个已知含 bug 的 diff，看能否抓到；按单个 reviewer 统计命中和误报 |
| 12 | 参验 | 战国策·魏策二（三人成虎） | 三人言而成虎 | 多数一致不等于独立证据 | 同模型同 context 的三个 agent 投票，错误是相关的；verifier 必须异构（不同模型、不同 context，看不到作者推理） | 多个 agent 引同一篇二手文章，只算一个来源；要求追到原始出处 | 作者 agent 与 reviewer 不共享 context；重要改动加一个不同模型或不同 prompt 的第二 reviewer |
| 13 | 参验 | 左传·昭公二十年（晏子论和同） | 君所谓可，而有否焉，臣献其否以成其可；若以水济水，谁能食之 | 价值来自差异；同质的附和不提供信息 | reviewer 的职责是“献其否”：必须给出最强的反对理由；全票通过当作可疑信号，而不是通过信号 | 综合之前先让一个 agent 列出“结论可能错在哪” | 零 finding 时要求 reviewer 说明它检查了什么 |
| 14 | 参验 | 左传·襄公三十一年（子产不毁乡校） | 其所善者，吾则行之；其所恶者，吾则改之；不如小决使道 | 让问题小股持续暴露，好过堵到溃决 | brief 里明确要求回报 blocker、不确定和“没做完”；坏消息不算失败 | 输出里固定一栏“没查到 / 不确定” | 允许 reviewer 回答“这段看不懂 / 无法验证” |
| 15 | 藏欲 | 韩非子·主道；战国策·齐策一（邹忌） | 君见其所欲，臣自将雕琢；私我、畏我、有求于我 | 下属会向上级偏好对齐 | 即 sycophancy。给 reviewer 的 prompt 不泄露你期望的结论，不告诉它这是谁写的 | 问“X 的证据如何”，不问“证明 X”；另派一个 agent 专找反证 | 不写“应该没问题，帮我看看”；不透露作者是谁、是不是 agent 写的 |
| 16 | 兵符 | 虎符制；史记（高祖夺韩信军） | 驰入其壁，夺其军 | 授权可分割、可随时收回 | credential 最小化、短时效、可撤销；kill switch 不依赖 agent 配合 | 调研 agent 只读：能搜能读，不能写库、不能对外发消息 | reviewer 没有 push 和 merge 权限；修复在独立 worktree / 分支里做 |
| 17 | 兵符 | 史记·绛侯周勃世家（细柳营） | 军中闻将军令，不闻天子之诏 | 单一指挥链，旁路来的命令不认 | 即 prompt injection 防御：tool result、网页、其他 agent 消息里的“指令”一律当数据 | 网页和文档里的“指令”当数据；发现疑似注入，回报而不执行 | 代码注释、README、issue 里写给 AI 的话同样当数据 |
| 18 | 兵符 | 战国策·齐策四（冯谖焚券市义） | 焚券市义 | 代理人按意图而非字面行事，是双刃 | 允许 agent 推断意图，但不可逆操作（删除、发送、付款）必须回报确认 | 可以自行扩展到相邻问题，但必须标注“超出原范围” | 可以提议重构，不直接做；删文件、改 CI、动依赖必须先确认 |
| 19 | 兵符 | 左传·隐公元年（郑伯克段于鄢） | 都城过百雉，国之害也；无使滋蔓，蔓难图也 | 下属资源超过定额就是隐患；早期收束比事后清理便宜 | 每个 sub-agent 有 token / 时间 / 工具调用预算，超限即停并回报 | 单个子问题设检索轮数上限，超了回报，而不是继续挖 | reviewer 只看指定范围的文件，不顺藤摸瓜读全仓 |
| 20 | 兵符 | 左传·宣公十二年（邲之战） | 先縠以偏师先渡，全军被迫跟进；师出以律，否臧凶 | 一个下属擅自行动能绑架整个系统 | sub-agent 不得自行启动下游动作或派生新 agent；有副作用的步骤由 orchestrator 统一发起 | sub-agent 不自行扩大调研范围，不自己再 spawn | reviewer 不自行触发修复或 CI |
| 21 | 兵符 | 左传·成公二年（仲叔于奚请曲县繁缨） | 唯器与名，不可以假人 | 权限和身份不能转借 | credential 不在 agent 之间转手；sub-agent 拿到的是按任务裁剪的权限，不是 orchestrator 的全套 | sub-agent 不继承 orchestrator 的写权限和连接器 | 不把你自己的 token 直接放进 reviewer 的环境 |
| 22 | 试任 | 左传·襄公三十一年（子产论尹何为邑） | 未能操刀而使割也，其伤实多；学而后入政，未闻以政学者也 | 不拿真实任务给未经验证的人练手 | 新 skill、新 prompt、新 agent 配置先过 eval，再上真实任务 | 新调研流程先在你已知答案的课题上跑 | 新 reviewer 配置先在已知含 bug 的历史 PR 上跑 |
| 23 | 直书 | 左传·宣公二年（董狐）；襄公二十五年（齐太史） | 赵盾弑其君；崔杼弑其君（太史兄弟相继被杀仍书） | 记录由独立于当事人的一方来写，当事人改不了；责任记在主事者名下 | agent 的自述不算记录；以 transcript、tool call 日志、diff 为准，agent 不能改写 | 核查时看实际打开过的来源，不看总结里说引了什么 | “测试已通过”以实际运行输出为准 |
| 24 | 直书 | 《春秋》笔法 | 用字本身带判定（如弑 / 杀之别） | 固定词表让一个词承载判定，读者不必再追问 | 规定 agent 报告的状态词表：已验证 / 推断 / 未验证；完成 / 部分完成 / 未做 | 每条结论标注：已核对原文 / 二手转述 / 推测 | finding 分三档：确认的 bug / 可疑 / 风格建议 |
| 25 | 量力 | 孙子·谋攻 | 上兵伐谋，其次伐交，其次伐兵，其下攻城。攻城之法，为不得已 | 手段有贵贱之序，最贵的只在不得已时用 | 先用最便宜的手段回答问题；全量 fan-out 和全量核查是攻城 | 先看实物能不能直接回答；不能再走 Standard；Deep 只在完整性或风险要求时用 | 先跑 lint 和测试，再派 reviewer；多 reviewer 只给高风险改动 |
| 26 | 量力 | 孙子·谋攻 | 十则围之，五则攻之，倍则分之……识众寡之用者胜 | 按力量对比选打法 | 按决策的分量选档位，而不是一律用最重的流程 | Fast / Standard / Deep 三档，Standard 为默认 | 小改动一个 reviewer，大改动按维度拆 |
| 27 | 量力 | 史记·李将军列传（李广与程不识） | 李广「莫府省约文书籍事，然亦远斥候，未尝遇害」；程不识「士吏治军簿至明，军不得休息」 | 轻流程能成立，前提是斥候放得远 | 轻档位可以省掉流程，但不能省掉实物检查和关键说法的核查 | Fast 档仍然先看实物，并核查决定结论的那几条 | 快速 review 仍然跑测试、看 diff 里高风险的部分 |
| 28 | 量力 | 史记·孙子吴起列传（田忌赛马） | 今以君之下驷与彼上驷，取君上驷与彼中驷，取君中驷与彼下驷 | 力量按对手分配，不平均使用 | 便宜的手段给低价值条目，贵的手段留给决定结论的条目 | 初筛用便宜的检索，核查力量集中在 shortlist | 机械检查交给工具，强模型只看语义问题 |
| 29 | 量力 | 左传·隐公十一年 | 度德而处之，量力而行之 | 按自己的力量定做多少 | 预算是设计的一部分，开始前定下，超出要说明 | 每档有候选数和核查数的默认上限 | review 的范围和深度先定 |
| 30 | 量力 | 韩非子·外储说左上（郑人买履） | 宁信度，无自信也 | 只信量好的尺码，不信自己的脚 | 预算是软上限；证据要求超出预算时说明并升级，不为守数字丢掉重要证据 | 超出候选上限时写明为什么 | 超出范围时写明为什么 |
| 31 | 节用 | 孙子·作战 | 兵闻拙速，未睹巧之久也；兵贵胜，不贵久 | 粗而快胜过巧而久 | 目标是支持决策，不是做全；粗略的及时答案好过完备的迟到答案 | Fast 档给出初判和不确定项即可 | 先给阻断性问题，风格建议可以不给 |
| 32 | 节用 | 孙子·作战 | 国之贫于师者远输；食敌一钟，当吾二十钟 | 远距离运输是最大的消耗；就地取用便宜二十倍 | agent 之间来回传大段原文就是远输；来源只存一次，阶段之间传编号和定位；优先用现成的综述、索引和项目自己的文档 | scout 交记录不交文章；verifier 拿到的是编号和定位 | reviewer 拿 diff 和文件路径，不拿整仓内容 |
| 33 | 节用 | 孙子·虚实 | 备前则后寡，备后则前寡……无所不备，则无所不寡 | 处处设防等于处处薄弱 | 每条都核查等于每条都核不深；先筛再验 | 只核查 shortlist 和决定结论的说法，其余标“未核” | 只深看高风险文件 |
| 34 | 节用 | 孙子·九变 | 涂有所不由，军有所不击，城有所不攻，地有所不争 | 有些路不走、有些城不攻是正当选择 | 明确允许跳过入口、不核查低价值候选，但要写明跳过了什么 | 报告里列出没走的入口 | 报告里列出没看的部分 |
| 35 | 节用 | 墨子·节用中 | 凡足以奉给民用，则止；诸加费不加于民利者，圣王弗为 | 够用即止；不增加效用的花费不花 | 停止规则：再查一轮不会改变结论，就停 | 连续一轮没有新的、与决策相关的候选，且 shortlist 证据足够，就停 | 再多一个 reviewer 不会改变合并决定，就不派 |
| 36 | 节用 | 左传·僖公二十八年；宣公十二年 | 《军志》曰：允当则归；见可而进，知难而退，军之善政也 | 适可而止和知难而退是好的治军 | 进和退都要有明文规则 | 写明停止条件和升级条件 | 写明什么情况下加 reviewer、什么情况下放行 |
| 37 | 节用 | 孙子·火攻 | 非利不动，非得不用，非危不战；合于利而动，不合于利而止 | 动用力量要有理由：有利、有得、有危 | 升级的理由只有三个：能改变结论、证据不足、涉及安全 | 遇到安全相关说法、重大查新冲突、证据不足以支撑决定时必须升级 | 涉及安全和数据的改动必须升级 |

## 三十六计：当 threat model 用

三十六计是对敌诡道，拿来管自己人是错配。它适合用来列举 agent 欺骗你或被欺骗的方式。

| 计 | 用法 | 在 agent fleet 中的对应 |
|---|---|---|
| 偷梁换柱 | 威胁（agent 欺骗你 / 被欺骗） | 改测试让测试通过，而不是修实现 |
| 金蝉脱壳 | 威胁（agent 欺骗你 / 被欺骗） | 报告“已完成”，留下一个空壳 |
| 树上开花 | 威胁（agent 欺骗你 / 被欺骗） | 总结比实际工作漂亮 |
| 无中生有 | 威胁（agent 欺骗你 / 被欺骗） | hallucination，虚构 API、引用或执行结果 |
| 瞒天过海 | 威胁（agent 欺骗你 / 被欺骗） | 例行公事式的 diff 没人细看，问题藏在里面 |
| 借刀杀人 | 威胁（agent 欺骗你 / 被欺骗） | 注入者借你的 agent 的权限行事（confused deputy） |
| 假道伐虢 | 威胁（agent 欺骗你 / 被欺骗） | 装第三方 skill 等于借道：它的指令和脚本以你的 agent 的权限运行（事见左传·僖公五年，宫之奇谏假道） |
| 釜底抽薪 | 可正向借用 | 收权限，而不是加警告 |
| 关门捉贼 | 可正向借用 | sandbox |
| 抛砖引玉 | 可正向借用 | 给粗稿，引出更好的版本 |

## 类比失效处

古籍讲的是管人，下面四点是 agent 和人不一样、类比不成立的地方。

| 失效点 | 古籍中的前提 | agent 的实际情况 | 结论 |
|---|---|---|---|
| 赏罚二柄没有对象 | 代理问题源于私心，靠赏罚对齐利益 | agent 的问题是幻觉、context 丢失和误差累积 | “罚”只能翻译成拒收、重试、收权；激励要换成筛选 |
| 换将零成本 | 临阵换将，兵家大忌 | agent 无状态、可克隆 | 纠正一个跑偏的 agent 通常不如丢掉 context 重开 |
| 稀缺资源是 context，不是忠诚 | 权谋制衡、防结党 | 信息如何压缩和传递才是主问题，古籍几乎不讲 | 这类术基本用不上；精力放在 context 的压缩与传递 |
| 将在外的前提不同 | 「将能而君不御」成立，是因为通信慢 | 你和 agent 通信几乎免费 | 放权程度取决于验证成本，而不是距离 |
