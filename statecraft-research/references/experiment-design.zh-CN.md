# 可证伪的实验方案

把一个 idea 落成最小实验时读这个。英文版是 `experiment-design.md`。

胜兵先胜而后求战，败兵先战而后求胜（《孙子·形篇》）。跑任何东西之前，先定下什么算赢。看到数字之后才定阈值的方案只会成功。

多算胜，少算不胜（《孙子·计篇》）。

## 方案必须包含的内容

| 部分 | 写什么 |
|---|---|
| 假设 | 一句话，并且实验有可能证明它是错的 |
| Baseline | 和什么比，其中要有最强的简单替代方案 |
| 受控条件 | workload、硬件、模型、数据和配置，固定并写下来，保证能重跑 |
| 指标 | 测哪些量，其中至少有一个可能变差。以 serving 系统为例：首个输出的时间、尾部延迟、吞吐、利用率、输出质量 |
| Ablation | 关掉哪些部分，用来说明效果从哪来 |
| 预期的代价 | 这个 idea 大概会牺牲什么，在跑之前写下 |
| 成功阈值 | 多大的效果才算数，以及它必须超过的多次运行间波动 |
| Stop/go 标准 | 什么结果下停手，什么结果下加大投入 |
| 失败之后 | 接下来会试什么或得出什么结论 |

## 经验规则

- **不要假设这个旋钮到处都能拧**。对一个模型有效的设置，换一个模型可能没有意义甚至有害。写明方案覆盖哪些模型或数据集。
- **同类比同类**。在匹配的负载下一次只变一个策略。评估自适应策略时，baseline 要包含它在其间选择的每一个固定设置。
- **目标是速度时一定带质量指标**。更快但更差是另一种取舍，不算赢。
- **先估噪声**。解读差异之前，把 baseline 多跑几次。
- **标出成本**。给出算力和时间的量级，没有实测就标成推断。
- **从最便宜的、可能失败的版本开始**。如果最小实验驳不倒假设，它只是演示，就按演示来称呼。
